## ส่วนที่ 3 — งานในโค้ด

### 3.0 ✅ ตรวจแล้ว: โค้ดจับคู่กับ RevenueCat ได้ถูกต้อง ไม่ต้องแก้

รันฟังก์ชันจริงจาก `SubscriptionService.js` (บรรทัด 153–229) กับค่า config จริงของโปรเจกต์ — **ผ่านทั้ง 9 เคส**

```
[1] findPackage หาแพ็กเกจเจอไหม
  PASS  findPackage(pro, monthly)         -> $rc_monthly
  PASS  findPackage(pro, yearly)          -> $rc_annual
  PASS  findPackage(lifetime, lifetime)   -> $rc_lifetime
[2] planFromIdentifier แปลง product id เป็นแผนถูกไหม
  PASS  'monthly'  -> pro
  PASS  'yearly'   -> pro
  PASS  'lifetime' -> lifetime
[3] เผื่อ Play คืนเป็นรูปแบบ subscriptionId:basePlanId
  PASS  'yearly:p1y'  -> pro
  PASS  'monthly:p1m' -> pro
[4] business แยกออกไหม
  PASS  'business_monthly' -> business
```

**ข้อสังเกตที่เจอระหว่างตรวจ:** `RC_PRODUCT_TO_PLAN` (บรรทัด 153–158) ยังเป็นค่าจากแอปอื่น —
`allslip_pro_monthly`, `allslip_business_yearly` ฯลฯ ซึ่ง **ไม่ตรงกับ product ID จริงสักตัว**

โชคดีที่ `planFromIdentifier()` มี fallback แบบเดาจากชื่อ (`includes('monthly')` → pro) ซึ่งจับได้ครบทุกกรณี
ตารางนี้จึงเป็น **โค้ดตายที่ไม่ก่อผลเสียตอนนี้** แต่ควรแก้ให้ตรงความจริงกันคนอ่านทีหลังเข้าใจผิด:

```js
const RC_PRODUCT_TO_PLAN = {
  monthly:  'pro',
  yearly:   'pro',
  lifetime: 'lifetime',
};
```

### 3.1 ปรับราคารายปีในโค้ดให้ตรงกับ base plan ใหม่

### 3.2 แบนเนอร์โปร + นับถอยหลัง 🆕

สร้าง `src/config/promo.js` — **แหล่งความจริงเดียว** ห้ามกระจายวันที่ไปไว้หลายไฟล์

```js
// เขตเวลาไทย = UTC+7
export const PROMO = {
  id: 'q4-2026',
  start: new Date('2026-10-01T00:00:00+07:00'),
  end:   new Date('2026-12-31T23:59:59+07:00'),
  discounts: { monthly: 20, yearly: 40 },   // ไม่มีแผน 6 เดือนแล้ว
};

export const isPromoActive = (now = new Date()) => now >= PROMO.start && now <= PROMO.end;

export function daysLeft(now = new Date()) {
  if (!isPromoActive(now)) return 0;
  return Math.ceil((PROMO.end - now) / 86400000);
}
```

**ที่ต้องไปแสดงผล:**

| จุด | ข้อความ | เงื่อนไข |
|---|---|---|
| หัว Dashboard | แถบบาง ๆ `ลดสูงสุด 40% · เหลืออีก {n} วัน` กดแล้วเปิด paywall | `isPromoActive()` เท่านั้น |
| `PaywallScreen.js` | ป้าย `-40%` บนการ์ด + ราคาขีดฆ่า | |
| `UpgradeModal.js` | เหมือนกัน | |
| `PremiumSettings.js` | เหมือนกัน | |

🔴 **ทุกจุดต้องเช็ค `isPromoActive()`** — ถ้า hardcode ว่า "ลด 40%" ไว้เฉย ๆ พอ 1 ม.ค. แบนเนอร์จะยังโชว์ทั้งที่ Play ปิด offer ไปแล้ว = **ผู้ใช้เห็นราคาไม่ตรงกับตอนจ่าย ซึ่งผิดนโยบาย Play**

### 3.3 🔴 บั๊กที่จะระเบิดตอนเปิด 10 ประเทศ — ราคา hardcode เป็นบาท

### 3.4 ลดตัวเลือกบน paywall เหลือ 3

ตอนนี้ `PaywallScreen.js:161` วนแสดง `['free', 'pro', 'business']` — **ไม่มี lifetime เลย** ทั้งที่โค้ดฝั่งซื้อรองรับแล้ว

**ที่ควรเป็น:**

```js
// การ์ด 3 ใบพอดี ไม่ต้องมีลิงก์ "ดูตัวเลือกอื่น"
// แมปเป็น package: $rc_monthly / $rc_annual / $rc_lifetime
[
  { plan: 'pro',      period: 'monthly'  },
  { plan: 'pro',      period: 'yearly'   },   // ใบเด่น
  { plan: 'lifetime', period: 'lifetime' },
]
```

- **1 เดือน** = ใบซ้าย ราคาต่ำสุดเพื่อลดแรงต้าน
- **12 เดือน** = **ใบเด่นตรงกลาง** มีป้าย "คุ้มที่สุด · ลด 40%"
- **Lifetime ฿2,990** = ใบขวา ทำหน้าที่ยึดราคาให้ ฿713 ดูถูก
- **Business** ย้ายไปหน้า Settings เป็น "สำหรับร้านค้า/ทีม — ติดต่อเรา"

> ตอนนี้ตัวเลือกลงตัวพอดี 3 ใบโดยไม่ต้องซ่อนอะไรไว้หลังลิงก์ — เป็นผลพลอยได้จากการตัดแผน 6 เดือน

### 3.5 ปรับ free tier (ตามข้อ 3.2 ของเอกสารกลยุทธ์)

```js
free: {
  limits: {
    transactions_per_month: Infinity,   // จาก 50 — เลิกกั้นการสร้างนิสัย
    budgets: 3,                          // จาก 1
    ai_scans_per_day: 5,                 // จาก 20
    ai_scans_per_month: 20,              // จาก 300 ← ข้อที่สำคัญที่สุด
    history_days: 90,                    // 🆕 กำแพงใหม่ ต้องเขียน gate เพิ่ม
    export: false,
    cloud_sync: false,
  },
}
```

⚠️ `history_days` เป็นข้อจำกัดชนิดใหม่ ต้องเพิ่มการตรวจในหน้า transactions/statistics/reports พร้อมข้อความชวนอัปเกรดที่สุภาพ ไม่ใช่แค่ซ่อนข้อมูลเงียบ ๆ

### 3.6 ปุ่ม "กู้คืนการซื้อ" 🔴 บังคับ

`restoreRevenueCat()` มีในโค้ดแล้ว แต่ **ต้องมีปุ่มให้กดในหน้า Premium** — Google บังคับสำหรับ non-consumable ถ้าไม่มีอาจถูกปฏิเสธตอนรีวิว

### 3.7 เตือนก่อนซื้อ Lifetime ทับ subscription

ถ้าผู้ใช้มี Pro รายเดือน/รายปีอยู่แล้วกดซื้อ Lifetime → RevenueCat **ไม่ยกเลิกให้อัตโนมัติ** ผู้ใช้จะถูกเก็บเงินซ้ำ

```
คุณมีสมาชิก Pro รายปีอยู่แล้ว หลังซื้อ Lifetime กรุณายกเลิกสมาชิกเดิม
ที่หน้าการสมัครสมาชิกของ Google Play เพื่อไม่ให้ถูกเรียกเก็บซ้ำ
```

### 3.8 ระบบแนะนำเพื่อน (พ.ย.)

| ส่วน | รายละเอียด |
|---|---|
| DB | ตาราง `referrals` ใน Supabase: `referrer_id`, `referee_id`, `code`, `redeemed_at` |
| โค้ด | สร้างโค้ด 6 ตัวจาก user id · Deep link `moneyma://ref/{code}` · หน้า `/r/{code}` บนเว็บ |
| ให้รางวัล | RevenueCat **promotional entitlement** `Premium` 1 เดือน ให้ทั้งสองฝ่าย เมื่อผู้ถูกชวนบันทึกรายการครบ 5 รายการ (กันการปั่นโค้ด) |
| ต้นทุนจริง | ค่า Gemini ~฿1–2/คน/เดือน · **ไม่มีค่าธรรมเนียม Play** |

### 3.9 Push เตือนบันทึกรายจ่าย (พ.ย. — ผลตอบแทนสูงสุดต่อแรงที่ลง)

Firebase มีอยู่แล้วในโปรเจกต์

| ประเภท | เวลา | ข้อความ |
|---|---|---|
| เตือนประจำวัน | 20:00 น. | `วันนี้ใช้ไปเท่าไรแล้ว ใช้เวลา 10 วินาทีจดไว้ก่อนลืม` |
| งบใกล้เต็ม | ทันทีเมื่อถึง 80% | `หมวดอาหารใช้ไป 80% ของงบเดือนนี้แล้ว` |
| สรุปรายสัปดาห์ | อาทิตย์ 19:00 น. | `สัปดาห์นี้ใช้ไป {n} บาท · หมวดที่ใช้มากสุดคือ {cat}` |
| โปรใกล้หมด | 15 ธ.ค. + 29 ธ.ค. | `ราคาพิเศษเหลืออีก {n} วัน` — 🔴 ส่งได้สูงสุด 2 ครั้งเท่านั้น |

⚠️ ต้องมีสวิตช์ปิดใน Settings และ **ห้ามส่งเกินวันละ 1 ครั้ง** — push ที่รบกวนคือสาเหตุอันดับต้น ๆ ของการถอนแอป

## ส่วนที่ 4 — เช็คลิสต์ทดสอบก่อนเปิดโปร

ทดสอบบน **มือถือจริงที่ล็อกอิน Play Store และเป็น license tester** (emulator ต้องเลือก image "Google Play" เท่านั้น)

| # | เคส | ผลที่ต้องได้ |
|---|---|---|
| 0 | ตรวจว่า offering `default` ตั้งเป็น **Current** และ entitlement ชื่อ **`Premium`** (P ใหญ่) มี product ครบ 3 ตัว | ถ้าไม่ตรง แอปจะไม่เห็นแพ็กเกจเลย |
| 1 | เปิดหน้า Premium | Console ขึ้น `RevenueCat initialized successfully` |
| 2 | หน้า paywall | เห็น 3 ใบ (1 เดือน / 12 เดือน / Lifetime) ราคาถูกต้อง มีป้ายส่วนลด |
| 3 | ซื้อ `monthly` + โปร | จ่าย ฿79 · เดือนถัดไปขึ้น ฿99 ในหน้าสมาชิก Play |
| 4 | ซื้อ `yearly` + โปร | จ่าย ฿713 · `subscriptions.plan = 'pro'` · `current_period_end` = +12 เดือน |
| 5 | ซื้อ `lifetime` (฿2,990) | `plan = 'lifetime'` · 🔴 **`current_period_end` = null** (ถ้ามีค่าจะถูกมองว่าหมดอายุ) |
| 6 | ถอนแอป → ติดตั้งใหม่ → กู้คืนการซื้อ | กลับมาเป็น lifetime |
| 7 | ผู้ใช้ที่เคยสมัครแล้ว เปิด paywall | **ไม่เห็นราคาโปร** (เงื่อนไข eligibility ทำงาน) |
| 8 | ปรับนาฬิกาเครื่องเป็น 1 ม.ค. 2027 | แบนเนอร์และป้ายส่วนลด**หายหมด** |
| 9 | ผู้ใช้ฟรีสแกนครบ 20 ครั้ง | เจอ paywall พร้อมข้อความชวนอัปเกรด ไม่ใช่ error |

## ส่วนที่ 5 — ลำดับการ deploy

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"   # JDK 17+
cd ~/projects/PFM

# 1. ล้างของเก่าให้หมด (CRA ฝัง env ตอน build — ไม่ล้างแล้วคีย์เก่าจะติดไป)
rm -rf build android/app/src/main/assets/public

# 2. build + sync
npm run build && npx cap copy android
npm run sync-android

# 3. build AAB → vc17 → ขึ้น open testing ก่อนเสมอ
```

**ข้อบังคับที่ตรวจแล้วห้ามพลาด:**
- `targetSdk 36` — **ห้ามลด** (เส้นตาย Play 31 ส.ค. 2026)
- `minSdk 24`
- package `com.moneyma.app` — **ไม่ใช่** `com.monyema.pfm`
- เซ็นด้วย `pfm-release-key.jks` alias `pfm-key` (SHA-256 `84:E2:F3:BF:…:0E:0F`)
- 🔴 **ห้ามยิงตรงเข้า production** — ขึ้น open testing ทดสอบให้ผ่านทั้ง 12 เคสก่อนเสมอ
